DB를 세팅하고 입력 폼을 만든다

Supabase 테이블을 만들고, 명함 정보를 입력받는 폼과 실시간 미리보기 뼈대를 세웁니다.

1

Supabase 프로젝트 + namecards 테이블 만들기

supabase.com → New Project → 이름: namecard-maker → 비밀번호 설정 → Create.
1~2분 기다리면 대시보드가 열립니다.

SQL Editor로 테이블을 한 방에 만듭니다:
왼쪽 메뉴에서 SQL Editor 클릭 → New query → 아래 SQL을 복사해서 붙여넣기 → Run (▶) 클릭.
SQL — 복사해서 SQL Editor에 붙여넣고 Run(▶) 클릭
-- ============================================ -- 명함 메이커 테이블 생성 SQL -- Supabase SQL Editor에 복사 → Run(▶) 클릭 -- ============================================ -- 1. namecards 테이블 생성 CREATE TABLE namecards ( id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY, share_id TEXT UNIQUE NOT NULL, -- 명함 고유 공유 코드 (URL에 사용) name TEXT NOT NULL, -- 이름 (필수) title_position TEXT DEFAULT '', -- 직함 company TEXT DEFAULT '', -- 회사명 phone TEXT DEFAULT '', -- 전화번호 email TEXT DEFAULT '', -- 이메일 address TEXT DEFAULT '', -- 주소 logo_base64 TEXT DEFAULT '', -- 로고 이미지 (base64 텍스트) style_name TEXT DEFAULT '다크 모던', -- 선택한 스타일 font_name TEXT DEFAULT 'Pretendard', -- 선택한 글꼴 created_at TIMESTAMPTZ DEFAULT NOW() -- 생성 시각 (자동) ); -- 2. share_id로 빠르게 조회하기 위한 인덱스 CREATE INDEX idx_namecards_share_id ON namecards (share_id); -- 3. RLS 비활성화 (수업용 — 실서비스에서는 반드시 켜세요) ALTER TABLE namecards ENABLE ROW LEVEL SECURITY; -- 누구나 읽기 가능 CREATE POLICY "누구나 명함 조회" ON namecards FOR SELECT USING (true); -- 누구나 저장 가능 CREATE POLICY "누구나 명함 저장" ON namecards FOR INSERT WITH CHECK (true); -- 누구나 수정 가능 CREATE POLICY "누구나 명함 수정" ON namecards FOR UPDATE USING (true);
✅ "Success. No rows returned" 메시지가 나오면 성공입니다. 왼쪽 메뉴에서 Table Editor를 클릭하면 namecards 테이블이 생겨 있습니다. 칼럼 11개가 보이면 완료.
💡 SQL 한 방이 칼럼 하나씩 만드는 것보다 빠른 이유 Table Editor에서 칼럼을 하나씩 추가하면 타입 선택, 기본값 설정을 11번 반복해야 합니다. SQL을 복사-붙여넣기하면 10초면 끝납니다. 칼럼 이름이나 타입을 잘못 입력하는 실수도 방지됩니다.

⭐ 첫 지시 — 전체 뼈대 + 입력 폼 + Supabase 연결

프롬프트
디지털 명함 메이커 웹앱을 index.html 한 파일로 만들어 줘. CSS와 JavaScript 전부 이 파일 안에 넣어. 두 가지 모드가 있어: 1. 만들기 모드 (기본) — 정보를 입력하고 명함을 만드는 화면 2. 보기 모드 — URL에 ?id=xxx가 있으면 DB에서 명함을 불러와 보여주는 화면 [만들기 모드 레이아웃] - PC: 왼쪽 입력 패널(400px) + 오른쪽 명함 미리보기 - 모바일: 위에 입력, 아래에 미리보기 입력 필드: 1. 이름 (필수) — placeholder "홍길동" 2. 직함 — "대표이사" 3. 회사명 — "우리회사" 4. 전화번호 — "010-1234-5678" 5. 이메일 — "hello@company.com" 6. 주소 — "서울시 강남구 테헤란로 123" 명함 미리보기: - 크기 가로 450px × 세로 270px (명함 비율 9:5.4) - 아무것도 안 입력했으면 예시 데이터로 보여 줘 - 입력 필드에 글자를 칠 때마다 실시간 반영 (input 이벤트) [보기 모드] - URL에 ?id=xxx 파라미터가 있으면 입력 패널을 숨기고 Supabase에서 해당 share_id의 명함을 불러와 명함만 크게 보여 줘 (전체 화면) Supabase 연동: URL: 여기에_본인_URL_붙여넣기 KEY: 여기에_본인_KEY_붙여넣기 supabase-js CDN: https://cdn.jsdelivr.net/npm/@supabase/supabase-js@2 상단 헤더: - "✦ 명함 메이커" 제목 - "정보를 입력하고 스타일을 골라 나만의 명함을 만드세요" 한 줄 성공 기준: 1. 이름을 치면 명함에 즉시 반영된다 2. URL에 ?id=test 를 붙이면 보기 모드로 전환된다 (아직 DB에 데이터가 없으니 "명함을 찾을 수 없습니다" 표시) 3. 6개 입력 필드가 전부 보인다

QR코드 + DB 저장 + 이미지 저장

명함 안에 QR을 넣고, 만든 명함을 Supabase에 저장하고, PNG로도 다운받습니다.

⭐ 명함 안에 QR코드 (vCard)

프롬프트
명함 안에 QR코드를 넣어 줘. 라이브러리: https://cdn.jsdelivr.net/npm/qrcodejs@1.0.0/qrcode.min.js QR 안에 vCard 형식으로 연락처 정보를 넣어 줘: BEGIN:VCARD VERSION:3.0 N:이름 ORG:회사명 TITLE:직함 TEL:전화번호 EMAIL:이메일 ADR:주소 END:VCARD 위치: 명함 카드 오른쪽 하단, 크기 60x60px 입력이 바뀔 때마다 QR도 재생성. 어두운 배경 스타일에서는 QR 뒤에 흰 패딩 4px. 성공 기준: 1. 명함 안에 QR이 작게 보인다 2. 정보를 바꾸면 QR도 바뀐다 3. 폰으로 스캔하면 연락처 저장 화면이 뜬다

⭐ "명함 저장하기" — DB에 쓰기

이 단계가 DB 연동의 핵심입니다. 버튼을 누르면 명함 데이터가 Supabase에 저장되고, 고유 공유 링크가 생성됩니다.
프롬프트
명함을 DB에 저장하고 공유 링크를 생성하는 기능을 만들어 줘. [저장 버튼] 1. 명함 미리보기 아래에 "💾 명함 저장하기" 버튼 2. 이름이 비어 있으면 "이름을 입력해 주세요" 경고 [저장 동작] 1. 8자리 랜덤 share_id를 생성 (영문소문자+숫자) 2. Supabase namecards 테이블에 INSERT: share_id, name, title_position, company, phone, email, address, logo_base64, style_name, font_name 3. 저장 성공 시: - 화면에 "✓ 저장되었습니다!" 메시지 - 바로 아래에 공유 링크 표시: "내 명함 링크: [현재URL]?id=[share_id]" - 링크 옆에 "복사" 버튼 → 클릭하면 클립보드에 복사 - "이 링크를 공유하면 누구나 내 명함을 볼 수 있습니다" 안내 [공유 링크로 접속했을 때] - 2단계에서 만든 보기 모드가 작동: URL에 ?id=xxx → DB에서 해당 명함 조회 → 저장된 스타일·글꼴·로고로 명함을 표시 - 입력 패널은 숨기고 명함만 크게 보여 줘 - 하단에 "나도 명함 만들기 →" 링크 추가 성공 기준: 1. 저장 버튼 → Supabase에 행이 추가된다 2. 공유 링크가 화면에 표시된다 3. 공유 링크를 새 탭에서 열면 명함이 보인다 4. 저장된 스타일·글꼴이 그대로 적용되어 있다
⚠️ 저장이 안 되면 RLS부터 확인하세요. Supabase 대시보드 → Authentication → Policies에서 namecards 테이블의 RLS가 꺼져 있는지 확인합니다.

⭐ GitHub Pages 배포 — 5단계

GitHub에 파일을 올리고, Pages를 켜면 영구 URL이 생깁니다.
터미널이나 Git 명령어는 하나도 안 씁니다. 전부 웹 브라우저에서 합니다.
GitHub Pages 배포 — 화면에 띄워 두고 따라하세요
[ 1단계 ] 새 저장소 만들기 github.com → 우측 상단 "+" → New repository • Repository name: namecard-maker • Public 선택 (Pages는 Public에서만 무료) • "Add a README file" 체크 • → Create repository 클릭 [ 2단계 ] 파일 올리기 저장소 페이지에서 Add file → Upload files 클릭 → VS Code의 index.html 파일을 브라우저에 드래그 → 아래 "Commit changes" 버튼의 메시지에 "명함 메이커 첫 업로드" 입력 → Commit changes 클릭 (images 폴더가 있으면 함께 드래그) [ 3단계 ] GitHub Pages 켜기 저장소 상단 탭에서 Settings 클릭 → 왼쪽 메뉴에서 Pages 클릭 → Source 항목에서 Branch: main 선택 → 폴더: / (root) 선택 → Save 클릭 [ 4단계 ] 1~2분 기다리기 "Your site is live at" 메시지가 나올 때까지 기다립니다. 새로고침하면 URL이 나타납니다: https://유저이름.github.io/namecard-maker/ [ 5단계 ] 확인 위 URL을 폰으로 열어서: 1. 명함 메이커가 뜨는지 확인 2. 명함을 만들고 저장 → 공유 링크가 잘 되는지 확인 3. 공유 링크를 다른 사람에게 보내서 열리는지 확인
💡 GitHub Pages는 배포까지 1~2분 걸립니다. Save 누르고 바로 URL을 열면 404가 뜰 수 있습니다. 1~2분 기다렸다가 새로고침하세요. Actions 탭에서 배포 상태를 확인할 수 있습니다.
⚠️ 코드를 수정한 후에는 다시 올려야 합니다. VS Code에서 코드를 고쳤으면 GitHub 저장소에서 다시 Upload files → 같은 이름의 index.html을 올리면 덮어쓰기 됩니다. 1~2분 후 사이트에 반영됩니다.

B

공유 링크가 "명함 없음"으로 뜰 때

프롬프트
명함을 저장하고 공유 링크를 새 탭에서 열었는데 "명함을 찾을 수 없습니다"가 뜨거나 빈 화면이야. 콘솔 에러: (붙여넣기) URL의 ?id= 파라미터 값이 DB의 share_id와 일치하는지, 보기 모드의 Supabase 조회 쿼리가 맞는지 확인해 줘.
C

GitHub Pages가 404일 때

프롬프트
GitHub Pages URL을 열었는데 404 에러가 떠. 확인할 것: 1. Settings → Pages에서 Branch가 main으로 선택되어 있는지 2. 파일 이름이 정확히 index.html인지 (Index.html 아님) 3. 저장소가 Public인지 4. Save 누른 후 2분 이상 기다렸는지 5. Actions 탭에서 배포 상태가 ✓인지 위 5개를 하나씩 확인하겠습니다.
D

QR코드 / 이미지 저장 / 스타일 문제

프롬프트
문제 상황: (아래 중 해당하는 것 골라서 쓰세요) - QR코드가 빈 상자로 보인다 - PNG 저장 시 QR이 포함 안 된다 - 스타일을 눌러도 안 바뀐다 - 글꼴을 눌러도 안 바뀐다 - 로고가 명함에 안 나온다 - 화면이 완전히 백지가 됐다 콘솔 에러: (붙여넣기) 원인 후보 3개와 확인 순서를 알려 줘. 코드는 아직 고치지 마.

수정 후 GitHub에 다시 올리기

따라하기
코드를 수정한 후 GitHub에 반영하는 방법: 1. GitHub 저장소 페이지로 이동 2. index.html 파일을 클릭 3. 우측 상단 연필 아이콘(✏️ Edit) 클릭 4. 전체 선택(Ctrl+A) → 삭제 5. VS Code의 index.html 내용을 전체 복사(Ctrl+A → Ctrl+C) 6. GitHub 편집기에 붙여넣기(Ctrl+V) 7. 아래 "Commit changes" 클릭 또는 더 쉬운 방법: 1. 저장소 페이지에서 Add file → Upload files 2. 수정된 index.html을 드래그 3. "Commit changes" 클릭 → 같은 이름이면 자동 덮어쓰기 → 1~2분 후 Pages에 반영
